# 共通取材ガイド・情報ブロック・研究準備

更新日：2026-09-18。対象は2026年茨城県議選のつくば市選挙区。ヒアリング未実施・候補者データ未登録の準備段階です。

この文書は提供された「オシセン！の研究対応設計案」を実装へ落とした運用案です。共通形式の効果が実証済みという意味ではありません。元の資料に記載された論文の原文を、この実装作業で新たに検証したとは扱いません。

## 1. 質問の用途を分ける

- P：政策命題への回答。候補者と利用者に同じ設問・版・尺度を用いる。
- H：本人が語る経験・選択・理由・条件。性格や誠実さを点数化しない。
- N：利用者の情報ニーズ。閲覧の入口や絞り込みに使い、相性や人物への加点に使わない。

Hの回答をPの欠測へ自動転記しない。本人の回顧、原音との一致、第三者資料による事実確認はそれぞれ別に扱う。

## 2. 全員に共通して聞く6問

実装上の定義は `lib/interviews.ts` の `interviewGuide`。変更時は質問の版と、全対象者への案内を揃える。

| ID  | 項目             | 本質問                                                                                                                     | 整理するときに残すもの                         |
| --- | ---------------- | -------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------- |
| H01 | 取り組みの背景   | 今取り組んでいる課題に関わるきっかけになった経験を、一つ教えてください。                                                   | 経験と現在の取り組みについて本人が説明する関係 |
| H02 | 判断と選択       | 二つ以上の目標を同時には満たせず、何かを選ぶ必要があった経験を教えてください。そのとき何を重視しましたか。                 | 状況・選択肢・選択・理由                       |
| H03 | 意見の相違       | 自分と異なる意見に接した具体的な場面と、その後の対応を教えてください。                                                     | 意見の違いと本人が説明する対応                 |
| H04 | 想定外への対応   | 取り組みが想定どおりに進まなかった例と、その後どうしたかを教えてください。                                                 | 当初の想定・経過・対応・振り返り               |
| H05 | 考えの変化・継続 | 新しい情報や経験に接して、自分の考えを見直した場面はありますか。変えた場合も変えなかった場合も、その理由を教えてください。 | 新しい情報・考慮したこと・変更または維持の理由 |
| H06 | 暮らしとの接点   | 日々の暮らしや地域での経験のうち、今の取り組みにつながっているものがあれば教えてください。                                 | 日常の経験と活動の関係                         |

共通の追加質問：

1. いつごろのことですか。
2. その中で、ご本人は何をしましたか。
3. 別の選択肢はありましたか。
4. その判断が当てはまる条件はありますか。

公職以外の仕事・地域活動・学校・暮らしの事例も認める。考えを変えたことだけを肯定的に扱わず、維持した理由も同様に尋ねる。答えのない箇所を推測で補わない。

## 3. 収録前に揃えること

- 30〜40分程度を試行の開始案とし、共通質問の時間枠、事前案内、追加質問、収録・編集条件を全対象者で揃える。
- 収録・文字起こし・公開範囲・本人による趣旨確認・訂正連絡先を事前に案内する。
- 私生活や第三者情報を、人物像の演出のために掘り下げない。
- 原音、文字起こし、発言区間ID、変更履歴を保持できる保存先と担当者を決める。
- 候補者本人の趣旨確認は、発言内容の事実性を独立に確認したこととは区別する。

## 4. 出典付きの情報ブロック

`InterviewDocument` は `schemaVersion: "1.0"` と `blocks` 配列で構成する。/research からダウンロードできるテンプレートは、H01〜H06の未収録の枠だけを持つ。氏名・仮の発言は入れない。

収録済みブロックの項目：

| 項目                              | 意味                                                                               |
| --------------------------------- | ---------------------------------------------------------------------------------- |
| id / subjectId / subjectLabel     | 安定したブロックID・対象者ID・表示名                                               |
| questionId / interviewOrder       | H01〜H06と実際の取材順。優劣や評価に使わない                                       |
| availability                      | `not_recorded` 未収録、`not_mentioned` 今回の回答では言及なし、`recorded` 収録済み |
| fields.experience                 | 本人が語った経験                                                                   |
| fields.action                     | 選択・行動                                                                         |
| fields.reason                     | 本人が挙げた理由                                                                   |
| fields.conditions                 | 条件・留保                                                                         |
| segments                          | 原文、前後の文字起こし、原音の開始・終了秒、全編URL、文字起こしURL、情報の種類     |
| recordedOn / answeredOn / version | 収録日・回答日・公開版                                                             |
| relatedPolicyQuestionIds          | 関連P設問のID。政策回答との同一視はしない                                          |
| corrections                       | 訂正・追記の版・日付・内容                                                         |
| reviews                           | 原音照合・文脈確認・本人の趣旨確認・公開承認                                       |

各 `fields` の値は `status: "stated"`、`text`、`segmentIds` の組、または `status: "not_mentioned"` のみ。要約は必ず存在する発言区間に接続する。言及なしの欄へ補足文を入れない。「経験がない」と読み替えない。

`segments` の各要素は次の形を使う。以下は型の説明であり、取材内容のサンプルではない。

```ts
{
  id: string;
  quote: string;
  contextBefore: string;
  contextAfter: string;
  startSeconds: number;
  endSeconds: number;
  fullUrl: string;
  transcriptUrl: string;
  informationKind: "self_report" |
    "recollection" |
    "official_record" |
    "editorial_summary";
}
```

前後の文脈が存在しない場合は空文字にできるが、文脈確認でその理由を確認する。開始・終了時刻は24時間以内で開始＜終了。元資料はHTTPSを要求する。YouTubeと直接音声・動画ファイルは該当区間へのリンクも生成し、それ以外は全編リンクと区間の時刻を提示する。自動で元サイトへ問い合わせたり、メディアを読み込んだりはしない。

## 5. 下書きから承認済み版まで

収録 → 文字起こし案 → 原音照合 → 区間抽出 → 共通形式の下書き → 別担当者の文脈確認 → 本人の趣旨確認 → 公開承認。

AIを用いる場合も、入力資料の範囲に限定し、否定・条件・時期・話者を保持する。原音・原文で照合する。訪問ごとに要約を生成しない。

`reviews` のキーは `audio`、`context`、`speaker`、`publication`。各記録は `reviewer`、`checkedOn`、`contentKey` を持つ。文脈確認者は原音照合者とは別にする。

`interviewContentKey(block)` が、確認対象の全文・出典・版・関連設問・訂正履歴を固定したキーを返す。/research からも内容キーを手動保存できる。内容や原音の時刻などが変わった場合、以前の確認記録のキーは一致しなくなり、表示対象から外れる。すべての確認記録が揃い、日付が収録・回答・訂正以降である場合のみ、プレビューへ出す。

これは署名・認証・権限管理の代わりではない。JSON内の自己申告を検証しているため、公開作業での権限確認と担当者確認は別途必要。/researchには公開操作がなく、読み込んでも通常ページへ情報は増えない。公開用レジストリ `lib/published-interviews.ts` の `publishedInterviewDocument` は空のままとする。/stories と候補者詳細のサーバーページが公開条件を確認し、承認済み本文だけを共通リーダーへ渡す。確認担当者や承認用の内容キーは公開用データから除く。レジストリをクライアントコンポーネントから直接インポートしない。

## 6. B/C表示と比較

- B：承認済みの同じブロックを、対象者ごとの取材順に並べる。
- C：同じブロックをH01〜H06ごとに並べ、同じ項目の2人分が続けて現れるようにする。スマホでは縦に続く。
- 本文・引用・文字数・原資料・公開版・訂正履歴を変更・省略しない。同じ `SourceBlock` コンポーネントで描画する。これは公開ページの本文表示にも共用し、公開ページにはB/C切り替えを設けない。
- `samePresentationMaterial` で、同じ対象者を選んだB/C間の完全な内容集合の一致を確認する。
- 対象者の入れ替えはチェックボックスから行う。一度に2人まで。得点順のソートはしない。
- `balancedSubjectOrder` は将来の割り付け計画で使える順序回転の純粋関数であり、本番の無作為割り付けを実装・実施したものではない。

比較するUI全体の効果を検証する準備であり、見出し単体やPodcast単体の効果を検証済みとは書かない。

## 7. ローカルの操作確認

/research の内容はタブ内のメモリだけに置く。ファイルのインポート、検証、B/C切り替えは通常のサイト利用から分離している。自動送信、ブラウザ永続ストレージへの保存、実参加者の募集・記録は行わない。

任意の同意後にのみ、文脈・原資料・関連政策への明示的な操作を記録する。画面に入ったことを読了として記録しない。記録する場面は `free_browse` と `comprehension_task` を分ける。イベントは表示条件、対象の情報ID、経過時間、同一操作の再クリック、同じ場面内での再クリックを持つ。記録の参加者IDは `local-check` であり、研究参加者のIDではない。

同意解除、手動消去、別資料の読み込み、比較対象の変更で操作記録を消す。B/Cの表示条件を切り替えると、記録と同意をリセットし、別条件の記録が同じ確認セッションに混ざらないようにする。ページの更新・移動・タブ終了でも消える。必要な場合だけ利用者がJSONを手動ダウンロードする。既にダウンロードしたファイルは、端末から別に削除する必要がある。

## 8. 根拠付き理解の採点準備

`scoreParticipantUnderstanding` は、割り当てた課題すべてを分母とし、「内容」と「根拠の発言区間」の両方が正しい課題の割合を参加者単位で返す。未回答は分母に残し、未回答の課題IDも返す。同じ課題への複数回答は勝手に最後のものを採用せず、先に採用回答のルールを決めるためエラーとする。

6〜8課題程度は試行案で、検証済み尺度ではない。実際の課題・正答・許容する根拠の組は、承認済み素材が揃ってから別担当者も確認して登録する。いま架空の取材内容に対する課題を公開しない。公開UIで参加者への課題提示・回答収集はまだ行わない。

研究を開始する前に、主要評価項目、主比較、必要人数、終了条件、除外・欠測の扱い、分析方法、実施責任者、同意と保存期間を固定する。18〜29歳は提案された対象者の範囲であり、現在の利用制限や募集開始を意味しない。政策関心・投票行動・記憶・主観的理解は別の指標として扱う。
