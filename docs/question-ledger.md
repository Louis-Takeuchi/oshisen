## 各質問に残すこと

- `id`：同じ政策命題を指す識別子。別の問いへの置き換えで使い回さない。
- `questionVersion`：質問本文・対象条件の版。
- `scaleVersion`：選択肢の文言・意味・対応値の版。
- `contextVersion`：補足説明の版。補足が変わった回答同士も自動照合しない。
- `theme` / `text` / `context`：分野、質問文、短い補足。
- `sections`：用語、現状・県との関係、主な論点、出典。現状は未確認、出典は空として明示。
- `status` / `verification`：草案・承認・廃止と、出典確認の状態。
- `selection`：採用・保留・不採用とその理由。不採用項目も削除せず記録する。
- `pendingChecks`：未確定の対象制度、比較基準、予算、権限など。
- `reviewedAt` / `baselineDate`：確認日と現状説明の基準時点。未確認なら `null`。

用語や論点の文章も運営の草案であり、先行研究や公的機関による承認済みの文章ではありません。現在の空の出典欄に、確認していないURLや引用を追加しません。

## 公開研究に使う前の手順

1. 住民・若者の自由回答と、議会・行政・候補者の公開資料をそれぞれ記録する。
2. 一問で一つの判断を尋ねられるか、県が判断する範囲や基準時点を説明できるか確かめる。
3. 採用候補と採用しない候補、それぞれの理由を台帳に残す。
4. 認知インタビューで、自分の言葉による言い換え、解釈、足りない情報、回答負担を確認する。
5. 本文・尺度・補足・出典を固定して版を発行する。変更時は版を上げ、過去の版と回答は書き換えない。
6. 利用者と全候補者へ同じ版を示す。候補者からは選択肢に加え、理由・条件・参照資料・回答日を受け取る。

質問内容の妥当性や理解の改善は、実装したことで確かめられたとは扱いません。

## 非集約型の照合

実装は `lib/policy.ts` の `comparePolicyAnswers` です。一回の呼び出しは一問・一候補者の回答を扱います。

1. 設問ID、質問版、尺度版、補足版の四つを照合する。
2. 表示対象の候補者IDと回答者IDが一致するか、今回の質問への本人回答か、公開可能な状態かを確認する。
3. 両者が5段階から選んだ場合だけ、選択肢が「同じ回答」「違う回答」かを返す。
4. 公開可能な理由・条件・出典を元の回答へ接続する。

候補者の回答は `verification: published` と `provenance: candidate_answer` に加え、候補者ID・回答日・公開日・今回の本人回答へ戻れる参照IDが必要です。照合時に第4引数へ表示対象の候補者IDを渡し、別の人の回答やID不明の回答を表示しません。日付は `YYYY-MM-DD` またはUTCのISO日時で保存します。公開日は回答日より前にできず、未来の回答日・公開日も受け付けません。出典に確認日を付ける場合も実在する過去または当日の日付を使います。参照元は公開URLがなくても安定した文書IDを持てます。URLを付ける場合は認証情報・空白・制御文字を含まないHTTPSに限定します。私的な回答提出先を不用意にリンクとして公開しません。これらのメタデータは公開条件であり、発言内容の事実性を自動認定するものではありません。

本人回答として公開する条件が揃わないものは、確認中または未掲載として扱います。公開前の回答・理由・条件・出典は照合結果に含めません。過去の公開発言や編集部の推測は今回の本人回答を埋めるために使いません。

中立の選択肢（値2）、判断保留、スキップ、未回答は別々です。判断保留には「情報が足りない」「考えがまとまっていない」を任意で残せます。利用者と候補者が両方とも照合できない場合も、両者の状態を失わず返します。

総合点、距離、重み、一致率、候補者の評価順は計算しません。「同じ回答」は理由、将来行動、人柄が同じという意味ではありません。関心テーマ（N）や取材情報（H）をこの照合に渡すAPIも設けていません。
