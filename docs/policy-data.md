# 政策ごとの根拠情報を登録する

候補者の各政策回答から、根拠資料と「その理由を本人が話している部分」へ進むためのデータ構造です。現在の仮名4名には実在の回答・資料・動画を登録していません。`policyEvidence` の全項目が空であることは、掲載漏れではなく現在の確認状況を表します。

## デモ数値との境界

`lib/data.ts` の `demoAnswerFixtures` は操作・計算確認専用です。根拠情報から数値を自動推論しません。根拠資料を追加しても、デモ数値やマッチング結果は変更されません。実データの回答値を公開する場合は、設問との対応、解釈方法、本人確認を別途確定する必要があります。

実在候補者の追加は、この登録作業だけでは完了しません。候補者の識別情報と取得済み回答を既存の候補者データ側で整備した上で、この対応表を追加してください。

## 登録場所と公開条件

`lib/policy-evidence.ts` の `policyEvidence` は、候補者IDから質問IDへの対応表です。値がない場合、または `verification: "unavailable"` の場合は未掲載表示になります。`pending` は編集作業中の状態で、本文、資料名、URL、動画を公開しません。

`verified` とした項目も、出典、本文、日付、分類が有効でなければ表示しません。URLの形式確認は取材や本人確認の代わりにはなりません。日付は実際に確認した `YYYY-MM-DD` の暦日を記録し、現在より先の確認日や確認日を越える回答日・公開日は受け付けません。不明な公開日は `null` とし、確認日や本人回答の回答日を推測で埋めないでください。

| provenance          | 扱う本文                         | 回答日 | 公開日                        |
| ------------------- | -------------------------------- | ------ | ----------------------------- |
| `candidate_answer`  | 本人が当該質問に答えた原文       | 必須   | 原資料に明記がなければ `null` |
| `public_document`   | 当該論点を裏付ける公開資料の原文 | `null` | 原資料に明記がなければ `null` |
| `editorial_summary` | 原資料に基づく編集部の要約       | `null` | 原資料に明記がなければ `null` |

本文の `text` は直接回答・原文と要約を明確に区別します。要約は本人の引用として表示されません。根拠となる原文へ直接進めるURLと、発行元の `label`、資料名の `title` を登録します。`kind` は既存の `ResourceKind`（`official_site`、`election_notice`、`social`、`assembly`、`youtube`）から選びます。

## 登録例の書式

以下は転記用の構造説明です。山括弧は未入力項目であり、実データでも実行可能な登録コードでもありません。このまま公開用データに追加しないでください。実在しそうなURL、日付、発言で置き換えることも避けます。

```text
<確認済み候補者ID>:
  <対象の質問ID>:
    verification: pending
    provenance: candidate_answer | public_document | editorial_summary
    text: <確認した原文、または明記した編集部の要約>
    source:
      label: <候補者本人・資料発行元の表示名>
      title: <原資料の正式名称>
      url: <実際に確認したHTTPSの原資料URL>
      kind: <原資料の種類に対応するResourceKind>
    answeredOn: <本人回答の実際の回答日。資料・要約はnull>
    publishedOn: <原資料に確認できる公開日。未確認ならnull>
    checkedOn: <この内容とURLを実際に確認した日>
    video: <該当動画が確認できる場合だけ下記項目を追加>
      verification: pending
      title: <実際の動画タイトル>
      url: <確認したYouTube watchまたはyoutu.be URL>
      startSeconds: <該当発言の開始位置。0以上の整数秒>
      publishedOn: <動画の公開日。未確認ならnull>
      checkedOn: <本人・発言・開始位置を実際に確認した日>
```

必要な確認を終えた資料のみ `verified` に変更します。資料が確認済みでも、動画の確認が終わるまでは動画の `verification` を `pending` にします。動画の設定がなくても、確認済みの根拠本文と原資料リンクは掲載できます。

## 公開前の編集確認

- 候補者本人・発行元と資料の出所を確認し、対象の質問に直接関係する内容かを読む。
- 本人回答、原文の抜粋、編集部の要約のどれに該当するかを明記する。
- 引用する範囲を必要最小限にし、前後の条件や留保を落として意味を変えていないかを確認する。
- 回答日・公開日・確認日を区別し、不明な日付を現在日で代用しない。
- 公式資料や公的記録へのリンクが、該当人物・該当論点の原資料を開くか確認する。
- 候補者間で同じ掲載基準・確認項目を適用する。資料がない候補者の回答を推測で補完しない。
- 動画は本人の発言と質問への関連を確認し、前提を聞き取れる開始時刻を選ぶ。文脈を変える切り取りにしない。
- 確認日以後に訂正・撤回が見つかった場合は公開を保留し、元資料と変更点を再確認する。

## YouTubeリンクの制約

`buildYouTubeTimestampUrl` は `https://youtube.com/watch?v=…`、`https://www.youtube.com/watch?v=…`、`https://youtu.be/…` のみ受け付けます。動画IDは英数字・`_`・`-`の11文字、開始位置は0〜86,400秒の整数です。別ホスト、認証情報入りURL、非標準ポート、埋め込み・リダイレクト用パス、不正な動画IDは拒否します。

入力の追跡パラメーターやフラグメントは引き継がず、`https://www.youtube.com/watch?v=<ID>&t=<秒>s` へ正規化します。形式の検証と、映像の本人確認・発言確認は別の作業です。

埋め込みプレイヤー、画像・動画の先読み、YouTube API呼び出しはありません。閲覧者が外部リンクを押して初めてYouTubeへ移動します。外部遷移は既存の同意制行動記録コンポーネントを通し、回答値・一致度の送信は追加しません。

## 画面への組み込み

```tsx
<PolicyEvidence candidateId={candidate.id} questionId={question.id} />
```

各質問の比較行に配置します。開閉項目の中で出典を確認でき、確認済み動画があれば「なぜそう考える？」「本人が話している部分を見る」と開始時刻を表示します。未確認の登録は公開UIに出さず、一次情報未掲載とデモ数値であることを表示します。

この変更にCMS、収集処理、外部サービス連携、デプロイ設定は含みません。テスト中の `example.invalid`、動画ID、日付、`TEST ONLY` は純粋関数の検証専用で、公開レジストリには一切含まれません。
