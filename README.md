# オシセン

2026年 茨城県議会議員選挙を想定した Phase 0 の体験用プロトタイプです。
「政策 → 候補者 → 人となり → 深掘り → 一次情報」の順で、候補者を知る入口を作ります。

## 現在の内容

- TOP、診断開始、8問の回答、結果、候補者一覧・詳細、理念、仕組み、情報源・公平性、プライバシー。
- 5段階の回答、スキップ、前の質問への移動、同一タブ内での再開・見直し。
- 等重みの政策一致度、比較した質問数、近いテーマ・違ったテーマ、表示境界の同点者を含む結果。
- 五十音順の候補者一覧、氏名検索、個別ページのURLコピー・メタデータ。
- 任意のローカル行動記録、書き出し・削除、A/Bの表示切り替え。
- Vercel本番環境の訪問数・ページ種類別閲覧数の集計。候補者別のURLや診断回答を送らず、プライバシーページから停止できます。
- ユーザー提供の手描き「オシセン!」ロゴ（青い文字・黄色のずらし・ピンクのハート）を使ったヘッダー、ファビコン、スマホ保存用アイコン、POPな画面、共有カード、読み込みエラー時の再試行画面。
- 候補者2人の政策比較、2段階以上違った設問の抽出、未掲載の分離表示（`/compare`）。
- ログイン不要の「気になる候補」保存と一覧、保存解除（`/saved`）。
- 8争点から5段階のサンプル回答を分類して候補者を探す（`/issues?theme=transport` など）。
- 診断後に重視テーマを最大3つ選び、テーマごとの近さを別表示。一致度・表示順への重み付けはしません。
- 政策ごとの出典、本人回答／原文／編集部要約の区別、検証済みYouTubeの該当時刻へのリンク（素材登録待ち）。
- 運営メンバー紹介（`/about#team`）。代表Ryo（大屋涼）、共同代表Louis（竹内琉瑛）の写真・担当・本人回答の人となりQ&Aを掲載。フッターやモバイルメニューから直接開けます。
- 公式Instagram・X、問い合わせメールへの導線（`/about#contact`）。メールアドレスのコピーにも対応しています。

掲載されている4名は、要求定義で指定された仮名です。写真・所属・年齢・経歴・本人の発言は未登録です。
`lib/data.ts` の `candidates[].answers` は未回答のまま保持し、`demoAnswerFixtures` を操作・計算確認専用に分離しています。
数値は実際の候補者の政策や回答を示しません。候補者ごとの外部リンクと動画も確認済み素材がないため未登録です。運営者提供のオシセン公式SNSとは別に扱っています。

## Vercelで公開する

このリポジトリは **Vercel用のNext.js** と、既存の **Sites用のvinext** の両方に対応しています。
アプリの画面とデータは共通です。Vercelへの公開操作は手動で行ってください。

1. Vercelで `Louis-Takeuchi/oshisen` をImportする。
2. Production Branchは `main`、Root Directoryはリポジトリのルート（未指定）にする。
3. Framework Presetは **Next.js**、Node.js Versionは **24.x** を選ぶ。
4. Build Commandは `npm run build:vercel`、Install Commandは `npm ci`。`vercel.json` に設定済みです。
5. Output Directoryは **Next.jsの既定値のまま**。`dist` や `public` に変更しない。
6. Deployする。追加のAPIキー・DB・環境変数は不要です。

独自ドメインが決まったら、必要に応じて環境変数 `SITE_URL=https://公開ドメイン` をProductionだけに設定して再デプロイします。
未設定時の共有画像URLはアクセス先ホストから生成されるため、VercelのPreview URLでも動きます。設定例は `.env.example` にあります。
既存のSitesの閲覧制限はVercelには引き継がれません。Vercel側の公開範囲・Deployment Protectionを確認してください。

```sh
npm ci
npm run dev:vercel
# 本番相当のビルド・配信チェック（公開操作は行いません）
npm run build:vercel
npm run test:vercel
# 本番相当のサーバーを自分で開く場合
npm run start:vercel
```

ローカルとVercelのビルドを揃えるため、Next.js標準のWebpackビルドを明示しています。
VercelにCloudflare Workerの `worker/index.ts` や `dist/` を指定する必要はありません。
設定の根拠：[VercelのNext.js対応](https://vercel.com/docs/frameworks/full-stack/nextjs)、[vercel.jsonの設定](https://vercel.com/docs/project-configuration/vercel-json)。

### 訪問計測を有効にする

`@vercel/analytics` を組み込み済みです。既存サイトを作り直したり、APIキーやデータベースを追加したりする必要はありません。
すでにサイトを公開していても、計測コードを反映した新しいデプロイが必要です。公開操作は手動で行ってください。

1. 既存のVercelプロジェクトの **Analytics / Web Analytics** を開き、有効化されていることを確認する。
2. この変更を含むコードをProductionにデプロイする。PreviewやSites、ローカルでは集計しません。
3. シークレットウィンドウ等で公開サイトのトップURLを直接開き、数ページ移動する。DNT/GPCが有効なブラウザでは集計されません。
4. 約30秒待ち、VercelのAnalyticsでProductionの訪問数・閲覧数を確認する。表示されない場合は停止設定、広告ブロック、対象の環境・期間、Vercel側の有効化状態を確認する。

有効化条件はサーバー側の `NODE_ENV === "production"` かつ `VERCEL_ENV === "production"` です。
`VERCEL_ENV` はVercelのシステム環境変数を使います。通常は手入力不要ですが、未設定の場合はプロジェクトの環境変数設定にある **Automatically expose System Environment Variables** を確認して再デプロイしてください。
初期設定では集計が有効ですが、`/privacy#visitor-analytics` からこのブラウザで停止できます。
実際にデータが届いたかの確認は、更新後の本番デプロイで行います。
公式手順：[Vercel Web Analyticsの導入](https://vercel.com/docs/analytics/quickstart)。

## Sitesでの開発と共通検証

Node.js 22.13以降が必要です。

```sh
npm ci
npm run dev
npm run lint
npm run typecheck
npm run build
npm test
```

`npm test` のルート検査は直前の `dist/` を使います。コード変更後は先にビルドしてください。
マッチング・保存・行動記録はNodeのテスト、ページは配信用WorkerへのHTTPリクエストで検証します。
Sitesの公開用ビルドでは、ブラウザで診断開始・回答選択・戻る・スキップ・結果表示・候補者詳細への移動を確認済みです。
本番だけ画面移動が失敗する問題を防ぐため、ブラウザの起動コードと遅延読み込みする画面移動処理を分離し、生成コードの回帰検査も行います。
Vercel用は `npm run test:vercel` がNext.jsの本番サーバーを一時起動し、全ページ・404・アイコン・共有画像・配信用設定を検査します。
両ビルドが生成するルート型の競合を避けるため、`npm run typecheck` はNext.jsのルート型を再生成してから型検査します。
ファビコン類の再生成は `npm run icons:generate`。元画像は `public/brand-logo.png` で、ユーザー提供のロゴ全体を使います。青い文字・黄色のずらし・ピンクのハートを含む絵柄を切り取らず、白い正方形に縦横比を保って収めます。以前の吹き出しアイコンや別の略字マークは生成しません。
`sharp` で16・32・48px入りのICO、180pxのAppleアイコン、192・512pxのPNGへ変換します。サイズ変換に外部フォント・画像サービス・APIキーは不要です。ロゴを差し替えたら再生成し、`app/layout.tsx` と `public/site.webmanifest` のアイコンURLの版（現在 `logo-2`）も揃えて更新してください。

2026-09-14時点で `npm audit --omit=dev` の実行時依存関係は既知の脆弱性0件です。
既存のSites用ツール等の開発用依存関係には監査警告が残っています。今回、既存配信環境を大きく変更する一括更新は行っていません。

## データと計測

回答はブラウザの `sessionStorage` に保存します。保存できない環境ではページ内メモリを使います。
比較候補と重視テーマも `sessionStorage`、明示的に保存した候補者IDだけは `localStorage` に保存します。端末間の同期はありません。
保存失敗時は操作を継続しながら一時保持であることを通知します。別タブの保存変更は同期し、無関係な保存キーには触れません。
これらの保存データのサーバー送信、アカウントへの紐付け、自動共有はありません。
操作記録は `/privacy#data-controls` で同意した場合のみ同じタブ内に保存し、回答の選択値・一致度は記録しません。
保存・解除は同意後のみ `candidate_save` / `candidate_unsave` として記録します。重視テーマの選択値は操作記録に含めません。
プライバシーページの確認付き削除で、保存候補とこのタブの回答・比較・重視テーマ・行動記録をまとめて削除できます。
削除が失敗しても画面上では回答を空にし、操作記録を停止します。保存領域の削除が確認できない場合はブラウザ側の削除を案内します。

実験表示を確認するには `/privacy?variant=policy` または `/privacy?variant=policy-humanity` で操作記録を有効にします。
同意時の表示条件は削除するまで保持します。前者は結果・詳細の人柄、経歴、インタビュー部分を非表示にします。
現在はローカルの動作確認用であり、参加者間の集計や実証の効果測定は行いません。

### 訪問集計とローカル操作記録の違い

Vercel Web Analyticsの訪問集計は、上記の任意・タブ内だけの操作記録とは別の仕組みです。
ローカル記録への同意を外部送信への同意として扱わず、`lib/analytics.ts` のイベントをVercelに転送しません。
カスタムイベント、候補者別の閲覧数、診断完了率などの収集は今回の対象外です。

- Vercel本番でのみ、訪問数とページ種類ごとの閲覧数を集計します。Cookieを使わず、Vercel側では接続時の情報から訪問者数やおおまかな地域等を集計します。IPアドレス等が通信で一切処理されないという意味ではありません。
- 候補者詳細の計測用URL・ルートを `/candidates/[id]` に統一し、すべてのクエリ文字列とフラグメントを除きます。既知のページだけを送信し、診断回答・一致度・候補者ID・保存／比較対象・重視テーマ・ローカル操作記録は送りません。
- HTTPヘッダーとHTMLメタデータの `Referrer-Policy: origin` で、このサイトからの参照元情報をオリジンに制限します。SDKの送信直前処理では `document.referrer` 自体を加工できないため、参照元URLにルート以外のパス、クエリ、フラグメントが含まれる訪問は計測を開始しません。意図的に少なめの集計になることがあります。
- `/privacy#visitor-analytics` の停止設定は `localStorage` に保存し、別タブにも反映します。DNT/GPCが有効、または保存設定が読み取れない場合も停止します。`/privacy#data-controls` のローカルデータ削除では、この停止設定を残します。ブラウザ側でサイトデータを全削除すると停止設定も消えます。
- この停止設定やローカルデータ削除は、すでに送られたVercelの集計データや配信ログの削除ではありません。通常のページ配信では実際のリクエストURL等をVercelが処理します。集計の保存期間や利用上限は契約プラン・設定を確認してください。

データ項目と基盤側の扱い：[Vercel Web Analyticsのプライバシー説明](https://vercel.com/docs/analytics/privacy-policy)。

## 本番データへの接続

### 運営メンバーのプロフィール

`lib/team.ts` に表示名・本名・役職・担当・写真・本人回答をまとめています。候補者データや政策マッチングには含めません。
回答の追加は本人から受け取った文面を `answers` の該当質問IDへ登録します。未回答や空欄は「本人の回答を準備中」と表示し、性格・経歴・趣味などを推測で補いません。
初期掲載は本人提供の「自分をひと言で」「休日」「最近ハマっていること」の3問。判断・失敗・開発のきっかけ・相方についての4問は、回答を受け取ってから追加します。
正式な法人・団体名や個人情報の管理責任者は、運営メンバーの紹介や問い合わせ窓口とは別に確定する必要があります。

公開写真は `public/team/oya.jpg` と `public/team/takeuchi.jpg`。元写真の画素・画像サイズは変えず、EXIF/XMP・IPTC・コメントだけを除去しています。
`scripts/import-team-photo.mjs` は JPEG の画像本体を再圧縮せず、元写真とのデコード画素一致を確認してから保存します。元画像は変更せず、既存の公開写真への上書きも拒否します。
新規取り込みは `node scripts/import-team-photo.mjs /path/to/photo.jpg oya`（または `takeuchi`）。差し替え時は対象画像をバックアップしてから取り込み、`lib/team.ts` の縦横サイズと表示位置・画像テストも更新してください。
カード内だけCSSで写真の表示範囲を調整し、「写真を大きく見る」でメタデータを除いた全体画像を確認できます。

### 公式SNS・問い合わせ先

運営者が提供した公式SNSと公開問い合わせ先を `lib/site-contact.ts` に集約しています。変更時はこのファイルを更新してください。
Instagramは `https://www.instagram.com/oshisen.official/`、Xは `https://x.com/OshisenOfficial`、メールは `oshisen0914@gmail.com` です。Instagramの共有用クエリ `stkn` はリンクに含めません。
`/about#contact` とフッターから公式アカウント・問い合わせ先へ進めます。仕組み・情報源・プライバシーの説明にも同じメールアドレスを使用しています。

SNSは通常の外部リンクだけで、SDK・投稿の埋め込み・新しいクリック計測は追加していません。候補者のSNS、政策の一次情報、候補者用の操作記録とは区別しています。
問い合わせは `mailto:` とアドレスのコピーで対応し、サイト内フォーム・送信API・自動送信はありません。利用者自身がメールアプリで送信します。診断回答・一致度・保存候補などは本文や添付に自動追加しません。
受信メールの送信元アドレスや本文は返信・内容確認のために扱うことを `/privacy` に記載しています。法人・団体としての正式な運営主体、管理責任者、編集・訂正の確認体制は引き続き別途確定が必要です。

### 候補者の本番データ

政策ごとの情報源・YouTube時刻リンクの型と登録手順は [docs/policy-data.md](docs/policy-data.md) を参照してください。
`lib/policy-evidence.ts` の確認済みレジストリだけを表示し、現在は全候補の登録を空にしています。数値デモを一次情報で裏付けたものとして扱いません。
CMS、候補者回答の取り込み、権限別編集・承認、県政の権限を解説する監修済み教材は未実装です。
CMSは認証・保存先・編集権限・公開承認・変更履歴を決めてから実装する想定です。

- 設問・本人回答・出典の取得方法と更新・訂正手順を確定する。
- 候補者の掲載資格、選挙区、氏名、写真、所属、経歴を一次情報で確認する。
- デモ専用の型と計算経路を本番データ用に切り替え、未回答は未回答として扱う。
- `lib/resources.ts` に確認済みHTTPSリンクとインタビュー情報を登録する。リンクコンポーネントは種別別イベントに対応済み。
- 候補者写真が揃ったら、同じ寸法・画角で配置し、候補者ごとのOG画像を設定する。
- 正式な運営主体・管理責任者、計測の収集目的・保存期間・同意手順を確定する。公開問い合わせ先は `lib/site-contact.ts` に登録済み。

サイトはプロトタイプのため検索エンジンへのインデックスを無効にしています。
本番データを掲載して検索公開する際は、`app/layout.tsx` のrobots設定、`public/robots.txt`、`next.config.ts` の `X-Robots-Tag` を合わせて見直してください。
検索抑制はアクセス制限ではありません。デモ回答のままで実在候補者との一致度として公開しないでください。
Social preview の制作記録は `docs/social-preview.md` にあります。
